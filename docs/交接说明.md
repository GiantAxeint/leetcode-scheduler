## 0. 一句话

一个本地跑的 LeetCode 间隔复习工具：**每道题自己带复习档位**，到日子就排进当天早/午/晚三班；题型卡只用来给题分类和当复习时的参考答案，不参与排期。

形态是**桌面窗口 + 托盘常驻**：点 X 只是缩到托盘，服务继续跑，Edge 扩展随时能录用；不再需要挂一个 cmd 黑窗。

## 2. 技术栈

- 后端：Flask + sqlite3（WAL），无 ORM，SQL 手写
- 前端：单页原生 JS（`app/web/app.js` 一个文件），无框架、无构建
- 桌面壳：pywebview 6.2（Windows 走 WebView2 后端，复用系统 Edge 内核）+ pystray 0.19（托盘）
- 扩展：MV3，content script 注入 LeetCode 页面悬浮卡；程序没开时用 `scj://` 协议把它拉起来
- 打包：PyInstaller onedir，`console=False`
- 测试：pytest，26 个用例（`tests/`）

目录：

```

  api.py        所有 HTTP 接口
  desktop.py    桌面壳：窗口 + 托盘 + 自启 + 协议注册 + 单实例唤起

  paths.py      打包资源定位（sys._MEIPASS vs 开发态）
  main.py       启动入口：找端口 → 起服务 → 开窗/浏览器
  scheduler.py  排期、档位推进、候补队列
  db.py         建表、迁移、设置项
  state.py      旧的卡状态机（已废弃，未删除，无引用）
  schema.sql    表结构
  web/          index.html / app.js / style.css
```

**线程模型**（改 desktop.py 前必须懂）：主线程归 `webview.start()` 的 Win32 消息循环；waitress 和 pystray 各占一个 daemon 线程。退出只有一条路：托盘「退出」→ 停托盘 → destroy 窗口 → `os._exit(0)`。

## 3. 数据模型（schema v7）

核心表：

**problem** —— 复习的主体

| 字段 | 说明 |
|---|---|
| `status` | `inbox` 待归纳 / `linked` 已归题型（归纳维度） |
| `phase` | `queued` 候补 / `active` 在途 / `done` 出池（进度维度） |
| `stage` | 0=还没复习过，1..5 对应 1/3/7/15/30 天 |
| `next_due` | 下次该复习的日期（工作日） |
| `last_reviewed_at` | 最后一次判定时间 |
| `pass_streak` / `fail_count` | 统计用 |
| `order_no` | 候补队列里的手动顺序 |

**pattern_card** —— 题型（归纳用）：标题、触发信号、一句话本质、骨架代码、坑、变形族、复杂度、分类
**card_problem** —— 题与题型多对多
**card_state** —— 旧的卡档位，**已不参与调度**，保留只为兼容，可随时删
**review_log** —— 每次判定：`problem_id`、`result`（`correct`/`wrong`/`skip`）、`stage_from`、`stage_to`、备注、耗时
**daily_plan** —— 当日任务：`plan_date` + `slot`(morning/noon/evening) + `problem_id` + `done`
**settings** —— 键值表

## 4. 业务规则（当前生效，改动前先读）

### 4.1 档位推进

基数表 `interval_days = [1,3,7,15,30]`，`stage` 1..5 对应。

```
答对：
  stage 0 → 2   （首答答对直接跳进 3 天档，跳过 1 天）
  stage n → n+1
  stage 5 → 出池（phase=done，不再排期）
答错：
  退一档（最低 1 档），下次间隔 = 该档基数 × lapse_factor（默认 0.5，四舍五入，最小 1 天）
  例：15 天档答错 → 退到 7 天档 → 7×0.5≈4 天
打折只影响这一次，下次答对回到该档完整基数
```

这条规则参考了 Anki 的 lapse 处理（间隔缩短、难度惩罚），刻意**没有**采用"答错归零"，因为一次手滑清零 30 天进度会让人不敢点"未答对"。

### 4.2 周末

- 周一到周五正常排班，**周六周日不自动排到期复习**
- 到期日落在周末 → 顺延到下一个工作日
- 周末仍然可以：手动录题选班次、拖拽、答对/未答对判定、写记录
- 周末录的题，`next_due` 直接写成下周一

### 4.3 三态队列

```
候补 queued ──补位──▶ 在途 active ──走完 5 档──▶ 出池 done
```

- 在途上限 `queue_limit`（默认 15），按**不同题目**算，同一题复习 4 次仍算 1 题
- 在途满时新题自动进候补，不拒收
- 出池 / 删除 / 手动移出 → 从候补队头补位
- 候补顺序可拖拽调整（`PUT /api/queued/order`）
- **逾期超过 7 天**的题自动退回候补，把名额让出来（`scheduler.recycle_stale`）

### 4.4 当日任务

- 早班：`stage=0` 的新题（配额 `morning_new`，默认 2），不够就用到期的补
- 午班：到期的题（`noon_due`，默认 2）
- 晚班：剩余到期（`evening_due`，默认 1）
- 计划**当天只生成一次**（快照），之后不自动补
- 卡片可拖拽换班次（`PUT /api/plan/<id>`）

### 4.5 录入

- 同一 `leetcode_id` 只录用一次，重复返回 409「此题已录用」
- 班次默认 `auto`：12 点前早班，18 点前午班，之后晚班
- 录题时间存 `created_at`（秒级）

### 4.6 判定

二元：答对 / 未答对。没有通过率、没有检验项计分（`check_item` 表还在，仅作记录，不影响调度）。

## 5. 功能地图

页面（顶栏）：今日 / 题型卡 / 题目 / 统计 / 设置

**今日**
- 顶部四个可点标签：在途 / 候补 / 待归纳 / 积压，点开是题目清单，可删除、可移到在途、可归档卡
- 三班卡片：答对、未答对、细想（三阶段复习）、归题型；可拖拽换班
- 逾期徽章（1–2 天橙、3 天以上红）
- 周末顶部提示"不自动排到期复习"

**题型卡**
- 网格卡片，点开编辑：标题、触发信号、本质、骨架、坑、变形族、复杂度、分类
- 弹窗下方列出该题型下的题，可移除（自动回待归纳）、可加入（搜索选题）

**题目**
- 录入表单（题号、标题、难度、标签、班次）
- 待归纳题型区：每行「归题型」「删除」
- 全部题目表：题号 / 标题 / 难度 / 归纳 / 阶段 / 删除
- 所有题目标题可点击跳 LeetCode，按难度着色（简单青绿 `#008F7E`、中等 `#B97E00`、困难 `#DD2247`）

**统计**
- 解题进度环（按难度）
- 自然年热力图 + 年份下拉、「YYYY 年共完成 N 次」（答对答错都算）
- 最近答对、最近 14 天、各档答对率、答错类型

**桌面程序（设置页最下面那块）**
- 「关闭窗口时」：缩进托盘（默认）/ 直接退出
- 「开机自启」开关：写 `HKCU\...\Run`，关掉时连旧的启动文件夹 `.lnk` 一起清
- 浏览器模式（`--headless`）下这两项自动置灰，后端返回 `mode: "headless"`

**浏览器扩展**
- LeetCode 题目页右下悬浮卡，抓题号/标题/难度/标签
- 点录用 → 2 秒 toast（成功/失败/已暂存/已自动启动主程序）
- 主程序没开时：先用 `scj://` 协议把程序拉起来（进托盘），最多等 8 秒重试一次；仍失败才进本地队列，每分钟探测补写

主要接口见 `app/api.py`，路由前缀 `/api`。桌面相关三个：

| 接口 | 用途 |
|---|---|
| `POST /api/ui/show` | 单实例唤起，把已有窗口叫到前面 |
| `GET /api/desktop/state` | 返回 `mode` / `close_action` / `autostart` |
| `POST /api/desktop/autostart` | `{enabled: bool}`，写或删注册表自启项 |
| `POST /api/review` | 判定；当天已判过返回 **409 `already_reviewed`**（`force:true` 可绕过，界面不暴露） |
| `POST /api/review/undo` | 撤回**今天最近一次**判定：恢复 `stage`、`next_due` 归今天、`last_reviewed_at` 回退到上一条，删掉该条 `review_log`，`daily_plan.done` 复位 |

判定按钮的行为：当天判定过，「答对 / 未答对 / 细想」置灰不可点，**只有「撤回」可用**（琥珀色）。卡片本身不变灰 —— 失误操作要留一个出口。

## 7. 踩过的坑（改代码前务必看）

| 坑 | 现象 | 正确做法 |
|---|---|---|
| **schema 里加依赖新列的索引** | 老库启动直接报 `no such column: problem_id`，所有接口 500 | 新列上的索引一律放到 `migrate()` 之后建；`init()` 里先建表、再迁移、最后建索引 |
| **Windows `SO_REUSEADDR`** | 端口被占用也能 bind 成功，新实例"以为"抢到 8765，实际访问的仍是老进程 | `free_port()` 不要设 `SO_REUSEADDR`，直接 bind 探测 |
| **并发 init 撞写锁** | 前端 `Promise.all` 两个请求同时进来，报 `database is locked` | `_INITED` 集合 + 锁，每个数据根只 init 一次 |
| **弹层被裁** | 悬浮卡 flash 挂在 `overflow:hidden` 容器里，`top:-44px` 被裁掉，用户看不到任何反馈 | 提示层挂 `document.body`，按 `getBoundingClientRect` 定位 |
| **覆盖运行中的 exe** | `cp -rf` 覆盖 `F:\WB-box\刷题调度` 时可能失败或进程仍是旧代码 | 部署前让用户关掉窗口；部署后必须重启才生效 |
| **PyInstaller 在沙箱里失败** | `os.remove(base_library.zip)` 报 `OSError SHFileOperation 0x2` | `--workpath` / `--distpath` 必须指向全新空目录 |
| **git push 被代理拦** | `github.com:443` 502 / connection reset | 仓库已设 `git config --local http.proxy ""`；本机需开 VPN（Clash 7890）才能直连；`api.github.com` 不受影响 |
| **git 协议不通时上传** | 空仓库上 `git push` 完全失败 | `tools/gh_upload.py` 用 GitHub API 逐个对象上传，可保留完整历史 |
| **列表页空白的排查** | 前端 `render()` 里 promise 拒绝时页面全空 | `render()` 有 catch，会把错误堆栈打到页面上，先看那个 |
| **`console=False` 后 print 崩** | windowed 打包后 `sys.stdout is None`，裸 `print` 抛 `AttributeError`，而且不会有任何提示 | 全项目禁止直接 print，走 `main._log` 或 `desktop.ShellLog`（后者同时写 `desktop.log`） |
| **串行扫端口吃掉 8.5 秒** | `existing_instance()` 顺序试 21 个端口，防火墙对未监听端口丢包不回 RST，每个等满 0.4s 超时 | 改成 `ThreadPoolExecutor` 并发探测，实测 8.55s → 0.57s；冷启动 9.7s → 1.9s |
| **系统代理劫持环回请求** | 开着 Clash/公司代理时 `http_proxy` 会把 `127.0.0.1` 也转出去，探测自家服务得到 502，程序以为「没开」 | 所有本机请求用 `build_opener(ProxyHandler({}))` 显式绕过，见 `main._LOCAL_OPENER` |
| **托盘没起来就 hide** | 通知区不可用（远程桌面/精简系统）时，点 X 隐藏窗口会把它彻底弄丢 | `_on_closing` 里先检查 `_tray_ok`，托盘起不来就放行退出 |

## 8. 未完成 / 悬而未决

1. **「当月」口径**：在途上限说的是"当月要复习的不同题目"，但实现是"当前在途总量"，没有按月重置。按月清零会让一批题凭空消失，暂时没做。
2. **今日计划是快照**：当天首次打开生成一次，之后新到期的题不会补进来。要做"实时补"需要重新设计（会让清单在做题中途变动）。
3. **晚班口述模式**：UI 写了"只口述不写码"，实际行为和其他班次一样，没实现差异化。
4. **`state.py` 已死**：卡的状态机不再被调用，留着没删，清理时要一并删掉 `card_state` 表和 `check_item` 的调度意义。
5. **一题多题型**：目前允许，用户还没表态要不要限制成一题一题型。
6. **桌面版遗留**：
   - 窗口尺寸/位置不记忆，每次开窗都是 1180×820 居中
   - 没有全局快捷键唤起窗口（只靠托盘和二次启动）
   - 打包体积 46MB，其中 PIL 占 13MB，可以裁插件瘦身
   - `scj://` 协议只写不清，卸载时要手动删 `HKCU\Software\Classes\scj`
   - 托盘气泡提示依赖系统通知，关闭通知中心就看不到「已缩到托盘」
8. **撤回的边界**：`review_log` 没存判定前的 `next_due`，撤回时统一归到今天。
   当天到期的题本来就是这个值，逾期题撤回后也该立刻重判，所以影响不大；
   但统计里「逾期天数」会短暂失真。要彻底解决得给 `review_log` 加一列 `next_due_before`（schema v8）。
9. **撤回只覆盖今天**：更早的判定已经带动过候补补位和排期，倒着撤会把链条搅乱，故意不做。
7. **扩展 B 档未闭环**：`scj://` 拉起已实现，但没有「程序已退出/正在启动」的状态回显，用户只能看到 2 秒 toast。

## 9. 给接手者的建议

- **先跑一遍测试**：`.venv\Scripts\python.exe -m pytest -q`，26 个用例，其中 `test_advance_*` 覆盖档位规则，`test_add_days_skips_weekend` 覆盖周末顺延。
- **改调度逻辑只动 `scheduler.py`**，`api.py` 里不要写业务规则。
- **改表结构必须加迁移分支**，`SCHEMA_VERSION` 加一，并考虑：老库里新列不存在时，任何引用该列的索引/视图/查询都会直接炸。
