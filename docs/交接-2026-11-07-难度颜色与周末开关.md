## 1. 问题一：新题标题变黑

### 现象

同一天录入的两道新题（3679、3439），列表里 3679 标题是橙色（中等难度色），3439 是黑色正文色。两题都带绿色「新题」标签，所以不是标签问题，是标题本身颜色不对。

用户原话：「又像上次那样变成黑色的了」——上次是日历视图的难度颜色，同一类问题。

### 根因链（四步）

```
① extension/content.js 抓难度
   document.querySelector('[class*="text-difficulty-"]')
   题目页是分段渲染的，抓取那一刻元素还没出现 → 拿到空串

② 入库 difficulty = ''
   api.py 的 INSERT 用 b.get("difficulty", "")，空串照写

③ 前端 diffClass('') 返回空字符串
   app/web/app.js:25

④ class 只有 "plink"，没有 d-easy/d-medium/d-hard
   → 命中 .plink { color: inherit }
   → 继承 .item .t → 继承 body 的正文色
   → 看起来和普通文字一样，是黑的
```

**真正的设计缺陷在第 ④ 步**：难度缺失时没有任何视觉提示，退化成了「正常正文」。数据缺了但看不出来。

### 修复（三层）

| 层 | 文件 | 改法 |
|---|---|---|
| 显示兜底 | `app/web/app.js` 的 `diffClass()` | 返回 `'d-unknown'` 而不是 `''` |
| 样式 | `app/web/style.css` | 新增 `.plink.d-unknown`：灰色 `#6f6d66` + 点线下划线 |
| 采集加固 | `extension/content.js` | 多候选选择器 + 文本长度 ≤6 字过滤，降低抓空概率 |
| 数据修复 | 数据库 | `UPDATE problem SET difficulty='中等' WHERE leetcode_id=3439` |

**为什么长度过滤**：多选择器可能匹配到包含整段文字的大容器，`textContent` 会是一大段。难度标签永远很短（「简单」「Easy」「中等」「Medium」最多 6 字符），用长度卡一下最省事。

**3439 的难度是「中等」**，来源：CSDN 题解、pkg.go.dev 题库索引、leetcode.cn 搜索结果三处一致。

## 2. 问题二：复习排期无法选择周末

### 需求

用户原话：「周六周日写的题，在复习时的时间分配，允许不跳过周六周日」。

现状是硬编码跳过周末：新题周末录入算下周一，间隔天数落到周末就顺延，周末也不生成当日计划。

### 实现

新增设置项 `skip_weekend`，默认 `1`（保持旧行为，不破坏已有数据）。

| 文件 | 改动 |
|---|---|
| `app/db.py` | `DEFAULT_SETTINGS` 加 `"skip_weekend": "1"` |
| `app/scheduler.py` | 加模块级 `_SKIP_WEEKEND` + `set_skip_weekend()`；`is_workday()` 在开关关闭时直接返回 `True` |
| `app/api.py` 的 `conn()` | 每次建连同步一次：`scheduler.set_skip_weekend(db.get_int(...) != 0)` |
| `app/api.py` 的 `api_settings_update()` | 保存设置后**额外**同步一次，立刻生效 |
| `app/web/app.js` | 设置页「节奏」面板加勾选框；`saveSettings()` 带上该字段 |
| `tests/test_scheduler.py` | 新增 `test_skip_weekend_off_allows_weekend` |

### 为什么用模块级全局变量

`is_workday` 被这些地方调用：`build_plan` / `add_days` / `due_date` / `next_workday` / `_next_free_day`。全都传一遍配置参数会污染一大片签名，而这是单用户桌面应用，不存在并发问题。所以选模块级状态 + 每请求同步。

### 踩到的坑

第一版只在 `conn()` 里同步，结果 PUT 设置后 `_SKIP_WEEKEND` 还是旧值——因为同一请求里 `conn()` 在写设置**之前**就执行完了。

修复：`api_settings_update` 末尾再同步一次。验证脚本：

```python
c.put('/api/settings', json={'skip_weekend': '0'})
print(scheduler._SKIP_WEEKEND)   # 必须是 False，不是 True
```

## 6. 遗留事项（按优先级）

1. **已有 `next_due` 不会按新开关重算**
   这是已知限制，不是 bug。历史日期是旧规则算出来的，切换开关只影响之后新算的。
   如果要让存量题目也重排，需要写一次性脚本遍历 `problem` 表重新调用 `advance`/`add_days`。动手前先备份数据库。

2. **难度仍可能抓空**
   现在只是「抓空也不变黑」，没有根治。彻底方案：服务端在 `difficulty` 为空时记一条待补清单，或者提供一个「重新抓取难度」的按钮。

3. **扩展需要用户手动重载**
   代码改了但 Edge 里跑的还是旧版。任何 `extension/` 下的改动都要提醒用户重载。

4. **打包目录堆积**
   `build_v7` ~ `build_v21`、`dist_v6` ~ `dist_v21` 有十几套，占空间。清理前先确认当前运行的是 `F:\WB-box\刷题调度` 那份，项目内 `dist_*` 都是历史产物，可以只留最近两套。
